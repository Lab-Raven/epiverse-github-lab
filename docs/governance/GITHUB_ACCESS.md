# Politique des accès GitHub — proposition à valider

| Rôle fonctionnel | Permissions techniques minimales envisagées |
|---|---|
| Direction du projet (Estelle) | Owner de l'organisation officielle à confirmer ; administration contrôlée |
| Leads de domaine | Write sur dépôts de travail ; Maintainer uniquement si besoin documenté |
| Développeurs | Write via branches et PR ; pas de secrets, pas d'admin |
| Relecteurs qualité / sécurité | Lecture et revue ; réglages de sécurité avec délégation contrôlée |
| Pédagogique | Accès read, le temps de l'évaluation, après validation |
| Anciens membres | Retrait des accès actifs après vérification, conservation de l'historique |

Dans le LAB personnel : **aucune invitation automatique**. L'appartenance au groupe doit être vérifiée par les responsables avant invitation.

Gouvernance de PR : un auteur ne peut pas valider sa propre PR. Deux revues indépendantes sur les changements sensibles dans l'organisation réelle si la taille d'équipe le permet. Aucun auto-merge agent.
