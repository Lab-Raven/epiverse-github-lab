# Politique de revue des Pull Requests

1. Toute modification de produit doit avoir un ticket et une branche dédiés.
2. PR limitée en taille, description d'impact, tests, risque de régression et preuve.
3. CI verte si fonctionnelle ; en cas de CI bloquée, **ne pas déclarer la PR validée**.
4. Reviewer différent de l'auteur ; CODEOWNERS et droits minimaux lorsque l'équipe officielle est validée.
5. L'auteur peut répondre et corriger, pas simuler une approbation extérieure.
6. Pour IAM, données, sécurité et déploiement : revue renforcée.
7. Assigner une issue ne prouve pas une contribution ; utiliser commits, PR, revue et tests liés.
8. Garder la PR #6 brouillon tant que l'incident Actions #7 est bloquant.

Ce LAB est privé, mono-utilisateur ; la revue indépendante nécessite une invitation distincte et explicite.
