# EpiVerse — GitHub LAB

> **Laboratoire de simulation non officiel.** Ce Project sert à tester la gestion de projet avec GitHub et ne représente pas l'avancement réel de l'application EpiVerse.

## Objectif

Tester une gouvernance et une chaîne de livraison complètes : exigences → backlog → planification → branche → pull request → tests CI → revue → validation → preuves → reporting.

## Fonctionnement

- **GitHub Issues** : besoins, tâches, bugs, risques et décisions.
- **GitHub Projects** : priorisation, Kanban, itérations, roadmap, capacités, jalons et preuves.
- **GitHub Actions** : contrôles documentaires, tests Python, sécurité et rapports.
- **Pull Requests** : revue humaine et traçabilité des changements.
- **Wiki / Discussions** : documentation, annonces et échanges.

## États

`Backlog → Ready → In progress → Review → Testing → Done`

`Blocked` identifie une tâche empêchée ; `Done` ne signifie pas automatiquement `Accepted`. La validation fait l'objet d'un champ distinct et d'une preuve.

## Vues

Portfolio, Backlog, Kanban, Sprint, Roadmap, Par domaine, Par personne, Risques et décisions, QA et revue, Livraisons et preuves, Pédagogie.

## Principes

1. Toutes les données de démonstration sont explicitement signalées `[LAB]`.
2. Le **Project #1 reste PRIVATE** ; le dépôt de démonstration est **PUBLIC** et ses Issues/PR sont publiques.
3. Les responsables réels, charges et délais ne sont pas inventés.
4. Aucun secret ni donnée personnelle sensible ne doit être enregistré.
5. Le dépôt officiel `epiverse-epitech/epiverse` reste complètement hors périmètre.
6. Toute configuration doit être vérifiée dans GitHub avant d'être déclarée opérationnelle.
7. Ne jamais inscrire d'information confidentielle dans une Issue publique, même liée à ce Project privé.
